# CSV の書き出しと取り込み

血圧の記録を CSV で書き出し、ファイルから取り込む。書き出す形式は CSV だけ。取り込みは、このアプリの CSV のほか、他のアプリが書き出したファイルも読む (→「他のアプリのファイル」)。

- 書き出し: サーバーが CSV を作る (`GET /api/v1/records/export`、`src/api/records.rs` の `export_records`)。
- 取り込み: ブラウザが CSV を読んで行に分け、確かめた行を JSON で送る (`POST /api/v1/records/import`)。CSV の解釈は `frontend/src/lib/import.ts`、置き換えは `src/api/records.rs` の `import_records`。
- 手書きの記録一覧の写真の読み取り (→ docs/ocr.md) と、他のアプリのファイルも、読み取った行を同じ一覧と同じ `POST /records/import` で取り込む。

## 書き出す CSV の形式

- 文字コードは BOM 付き UTF-8、改行は CRLF。区切りとクォートは RFC 4180 (`csv` クレート)。
- 1行目はヘッダー。列は次の5つで、この順に並べる。

| 列           | 中身                                                    | 例                 |
| ------------ | ------------------------------------------------------- | ------------------ |
| `measuredAt` | 測定日時。ユーザーのタイムゾーンでの `YYYY-MM-DD HH:MM` | `2026-09-25 07:15` |
| `systolic`   | 収縮期血圧 (整数)                                       | `124`              |
| `diastolic`  | 拡張期血圧 (整数)                                       | `82`               |
| `pulse`      | 脈拍 (整数)。未入力なら空                               | `60`               |
| `memo`       | メモ。無ければ空                                        |                    |

- 日時は UTC でなく、個人設定のタイムゾーン (`users.timezone`) の時刻にし、オフセットを付けない。表計算ソフトで開いたときに画面と同じ時刻に見え、日時として読まれるため。
- DB の主キー (`id`) は含めない。取り込みは id でなく日付で突き合わせるため。
- 対象は常にそのユーザーの全件で、測定日時の古い順。
- ファイル名は `Content-Disposition` で `bp-records-<ユーザーのタイムゾーンでの今日の日付>.csv` を付ける。

## 取り込める CSV

書き出した CSV はそのまま戻せる。加えて、表計算ソフトで保存し直したものも読む。

- 文字コード: UTF-8 として読めなければ Shift_JIS として読む (日本語の Excel で「CSV (コンマ区切り)」を選んで保存した形)。先頭の BOM は取り除く。
- 改行: CRLF と LF のどちらも、混ざっていても読む。空行は読み飛ばす。クォートの中の `,`・改行・`""` を扱う。
- 列: ヘッダーの名前で対応づける。順序は問わず、余分な列は無視する。
  - `measuredAt`・`systolic`・`diastolic` は必須。無ければファイルごと読み込まない。
  - `pulse`・`memo` は無くてもよい。
- 日時 (`measuredAt`)
  - オフセットの無い値は、個人設定のタイムゾーンの時刻として読む。
    - 日付と時刻の区切りは空白か `T`。日付の区切りは `-` か `/`。月・日・時はゼロ埋めでなくてよい (`2026/9/1 7:10`)。
  - オフセット付きの値 (`Z`・`+09:00` など) は、個人設定のタイムゾーンに換算する。
  - 秒は書いてもよいが、0 でなければ不正な日時として扱う。記録は分単位で、切り捨てると日時が黙って変わるため。
  - 日付だけ (`2026-09-01`) の行には、朝/夜の時間帯 (`users.morning_*`・`evening_*`) から仮の時刻を振る。手書きの記録一覧の読み取りと同じ規則 (`fillPlaceholderTimes`)。
    - 日ごとに時刻の無い行を数え、前半を朝・後半を夜にする (奇数なら朝を1件多く)。
    - 時間帯の中央の時刻から、同じ日・同じ時間帯の行ごとに1分ずつずらす。
- 数値は10進の整数だけを受け付ける (前後の空白は許す)。`pulse` は空なら未入力。

## 他のアプリのファイル

他の血圧記録アプリ・血圧計のアプリが書き出したファイルを、取り込みの行に直す。形式ごとに読み方が違い、行にした後 (検証・差分の確認・置き換え) は、このアプリの CSV と同じ。

- 読み方は、選んだファイルの拡張子と種類で決める (`importFileType`)。
  - `.pdf` は PDF、`.zip`・`.xml` は「ヘルスケア」の書き出し、それ以外は表の形のテキスト。
- Gemini に送るのは、表の形のテキストの先頭の数行と、PDF の全体だけ。「ヘルスケア」の書き出しは送らない。
  - 枠・同時に1件・使った額の数え方は、写真の読み取りと同じ (docs/ocr.md)。読み取りが無効なら、表の形のテキストはこのアプリの CSV だけを読み、PDF は読めない。
  - 送る前に、送り先・送るもの・目的を示して、そのつど同意を得る (`file-read-consent-dialog.svelte`)。同意は記録しない。何度もする操作でなく、送るものの重さ (先頭の数行か、全体か) もそのつど違うため。写真を送る同意 (`users.ocr_consented_at`) とは別で、サーバーは確かめない。

### 表の形のテキスト (CSV など)

- このアプリの CSV として読めれば (必須の列がある)、そのまま読む。読めなければ、列の意味を Gemini に決めてもらう。
- 送るのは、空行を除いた先頭の12行 (1行は400文字まで、`tableSample`)。値は読み取らせず、どの列が何かだけを答えさせる (`POST /api/v1/ocr/table-columns`、`src/ocr_files.rs` の `TableColumns`)。
  - 行数によらず費用が一定で、数値を機械的に移すので読み違いが入らず、Gemini に送る記録が数件で済むため。
- 答えさせるもの:
  - 区切り (カンマ・セミコロン・タブ)、データの前にある行の数、数字だけの日付の年・月・日の並び、日時が UTC か。
  - 1行に含まれる測定ごとの列の番号 (日付・時刻・上・下・脈拍・メモ) と、見出しで決まる朝・夜。1行に朝と夜が横に並ぶ表は、測定ごとに1組ずつ。
- 行を記録に直すのはブラウザ (`frontend/src/lib/import-table.ts` の `parseTableImport`)。
  - 日付は、年が先の形・年が後ろの形 (並びは答えに従うが、13 以上の数は月にしない)・月の名前の形を読む。全角は半角にそろえ、曜日などの括弧書きは除く。
  - 時刻は、24時間・AM/PM・午前/午後・「時」「分」の形を読む。日付と同じ欄でも別の欄でもよい。
  - 秒は捨てる。他のアプリは秒まで書くものが多く、秒のある行を読めない日時にすると全行が取り込めなくなるため (このアプリの CSV では捨てない、「取り込める CSV」)。
  - オフセット付きの日時と、UTC と答えた表の日時は、個人設定のタイムゾーンに換算する。
  - 数値は、小数点以下の 0 (`120.0`) と後ろの単位 (`120 mmHg`) を除く。
  - 上と下がどちらも空の測定は記録にしない (朝と夜が横に並ぶ表の、測っていない回)。
  - 複数の測定が同じメモの列を指すときは、その行の最初の記録にだけメモを付ける。
- 血圧の記録の表でないと答えたら、読み取れなかったと伝える。

### PDF

- 全体を Gemini に送り、測定ごとの記録を読み取らせる (`POST /api/v1/ocr/document`、`src/ocr_files.rs` の `read_document`)。10MB まで。
- 返す形は、手書きの記録一覧の読み取りと同じ行 (`OcrReading`)。日付は、年が書かれていれば `YYYY-MM-DD`、無ければ `MM-DD` (年は手書きと同じ規則で補う)。
- 行は、読み取りの自信も見る (`memoRowStatus`)。自信のない行は「要確認」にしてチェックを外す。
- 記録が多く、出力が上限 (`maxOutputTokens`) で途中で切れたら 422 (`ocr_document_too_long`)。期間を分けたファイルなら読めるので、Gemini の失敗 (502) と分ける。使った額は引く。

### 「ヘルスケア」の書き出し (zip)

- iPhone の「ヘルスケア」が書き出す zip の中の XML から、血圧の記録を取り出す (`frontend/src/lib/apple-health.ts`)。形が決まっているので Gemini は使わず、ブラウザの中だけで読む。
- XML は 1GB を超えることがあるので、全体をメモリに載せない。zip の一覧 (セントラルディレクトリ) から XML の位置を引き、その部分だけを展開しながら (`DecompressionStream`) 流して探す。
  - XML の名前は iOS の表示言語で変わるので、名前では決めない。XML のうち、診療の文書 (`export_cda.xml`) でないものを読む。
  - 取り出し済みの XML をそのまま選んでも読む。
- 記録は1件が1つのタグ (`<Record … />`) なので、XML 全体は解釈せず、タグを文字列で探して属性を読む。
  - 収縮期と拡張期は別々の `<Record>` で、同じ測定は `startDate` が同じ。`<Correlation>` の中にも同じ `<Record>` が重ねて書かれるので、`startDate` で1件にまとめる。
  - 脈拍は、血圧と同じ `startDate` の心拍数の記録があれば使う。血圧の日時を集めてから、もう一度流して探す (心拍数が血圧より後ろに書かれているとは限らないため)。
  - 単位が kPa の値は mmHg に直す。日時は個人設定のタイムゾーンに換算し、秒は捨てる。

## 行の検証

- 行ごとに、記録を1件登録するときと同じ規則で確かめる (`validateRecordForm`、サーバーは `validate_bp_values`)。
  - 日時が正しい・明日以降でない。
  - 収縮期 60〜260・拡張期 30〜180・脈拍 30〜220 (mmHg・回/分)、収縮期 > 拡張期。
- 規則に合わない行は、ファイル全体を拒まずに、その行だけを取り込みの対象から外す。直せば対象に戻る。
- 利用者が外した行も対象にしない。対象に残った行だけを送る。
- サーバーは送られた行をもう一度すべて確かめる。1行でも不正なら何も変えず、422 で不正な行の index と理由をまとめて返す (`error.rows`)。
- 1回に送れるのは 10,000 行まで (`MAX_IMPORT_RECORDS`)。

## 取り込みの意味: 行のある日を丸ごと置き換える

- 置き換えるのは、対象の行がある日だけ。その日の既存の記録をすべて消し、送った行を入れる。
  - 対象の行が1件も無い日の記録には触らない。範囲をまるごと置き換えると、CSV に書かれていない日の記録まで消え、取り込みが一括削除の手段になるため。
  - 日の区切りは、取り込むときの個人設定のタイムゾーン。
  - その日の既存の記録のうち CSV に無いものは消える。
- 送る `from`・`to` は対象の行の最も古い日〜最も新しい日。置き換える範囲ではなく、行がその中に収まっているかの検証にだけ使う。
- 削除と挿入は1つのトランザクションで行う。失敗したら何も変わらない。
- 既存の行を直す (UPDATE) 経路は持たない。同じ内容の行も消して入れ直すので、id と版番号は新しくなる。
- 同じ CSV をもう一度取り込んでも、記録の中身は変わらない。

## 差分の確認と、確認の後の変更

- 送る前に、対象の範囲の既存の記録を取得し、置き換える日ごとに次の3つに分ける (`buildImportDiff`)。
  - `added`: CSV にあって既存に無い行。
  - `removed`: 既存にあって CSV に無い行 (消える)。
  - `unchanged`: 日時・上・下・脈拍・メモがすべて一致する行。同じ内容の行が複数あれば、件数分だけ対応づける。
- 「変更なし」は確認のための分類で、サーバーでは他の行と同じく消して入れ直す。
- 確認の後にほかの端末などで置き換える日の記録が変わったら、取り込まずに止める。
  - 送るときに、確認に使った既存の記録のうち置き換える日の分の `id` と `version` を `expected` に入れる。
  - サーバーは消した記録の `id`・`version` の組が `expected` と過不足なく一致するかを見て、違えばロールバックして 409 (`record_conflict`) を返す。
  - 消す前に読んで比べず、消した結果 (`RETURNING`) で比べる。SQLite で読みから書き込みへ昇格するときの衝突 (`SQLITE_BUSY_SNAPSHOT`) を避けるため。
